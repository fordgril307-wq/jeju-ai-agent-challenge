# 2안-B 제주 안심 팩트체크 에이전트 — 기능명세서

> 제주 AI·빅데이터 활용 AI Agent 개발 챌린지 · 팀 미나리 백김치 · v1 (2026-11-17) · 아이디어 제안: 팀원

## 1. 개요

| 항목 | 내용 |
|---|---|
| 한 줄 정의 | 여행객의 제주 관련 불안 문의를 받아, 데이터로 사실을 확인하고 실제 개선 노력까지 담은 답장을 만들어 주는 에이전트 |
| 직접 쓰는 사람 | 제주 숙박·관광업 소상공인 (펜션·게스트하우스·소규모 호텔 운영자, IT 비전문가) |
| 쓰는 순간 | 손님의 "제주 괜찮아요?" 문의, 예약 변경 상담, 숙소 안내문 준비 |
| 받아 가는 것 | 3단 답장 초안(한·중·영), 근거 카드(출처 링크), 숙소 비치용 안심 안내문 |
| 수혜자 | 여행 예정자 (근거 있는 정보), 관광업계 (신뢰 회복) |
| 핵심 가치 | 반박에서 끝나지 않고 **공감 → 사실 판정 → 실제 노력**까지 연결된 답변 |

## 2. 답변 구조 (핵심)

| 단계 | 내용 | 규칙 |
|---|---|---|
| ① 상황 판단·공감 | 걱정에 공감, 실제 문제였던 점은 먼저 인정 | 사실인 부분 축소 금지 |
| ② 사실 판정 | 데이터로 판정: **사실 / 일부 사실 / 사실 아님 / 확인 안 됨** | 불리한 통계도 공개, 기준 시점·출처 표시 |
| ③ 실제 노력 (조건부) | 그 걱정과 직접 관련된 시행 중인 조치 | 효과 수치 있는 조치 우선, 없으면 생략 |

### 답변 예시 (형식 예시 — 수치는 출처 확보 후 확정)
> Q. "실종 사고가 많아서 제주 가기 무서워요"
>
> ① 걱정되실 만해요. 실제로 실종 신고 처리 과정에 문제가 있었던 사례가 확인됐습니다.
> ② 다만 제주의 실종 신고는 인구 대비로 보면 전국 평균 수준입니다. (경찰 통계 · 기준 연도 표시)
> ③ 이후 제주도와 경찰은 '실종·위기사건 대응협의체'를 꾸리고 CCTV 집중관제와 AI 실종자 추적 플랫폼을 수색에 연계했습니다. (2026.9)

## 3. 사용자 시나리오

| # | 상황 | 사용자 입력 | 에이전트 결과 |
|---|---|---|---|
| S1 | 치안 불안 문의 | 손님 메시지 붙여넣기 "요즘 실종 사고 많다던데…" | 3단 답장(한국어) + 근거 카드 |
| S2 | 외국인 손님 문의 | 중국어 메시지 | 언어 자동 감지 → 중국어 답장 + 한국어 번역 확인용 |
| S3 | 렌터카 걱정 | "제주 렌터카 사고 많지 않아요?" | 렌터카 사고 통계 판정 + 안전 운전 구간 안내 |
| S4 | 물가 걱정 | "제주 밥값 바가지 심하다던데" | 외식비 지역 비교 판정 + 착한가격업소 안내 |
| S5 | 결항 걱정 | "다음 주 금요일 비행기 결항될까요?" | 날씨 예보·운항 현황 기반 안내 (예측 단정 없음) |
| S6 | 안내문 제작 | "숙소에 붙일 안심 안내문 만들어 줘" | 주제별 한 장 안내문 (한·중·영) |

| F2 | 주장 분해 | 문의 속 확인할 주장 추출, 주제 분류 (치안·실종 / 렌터카 / 물가 / 결항 / 기타) | 문의 | 주장 목록 | P0 |
| F3 | 근거 조회·계산 | 주제별 도구로 공식 통계 조회, 비율·추세 계산 | 주장 | 근거 수치·출처 | P0 |

## 5. 에이전트 동작 흐름

```
① 문의 입력 ── 언어 감지, 개인정보(이름·연락처) 자동 가림
② 주장 분해 ── "실종 사고가 많다" → 주제: 치안·실종
③ 근거 조회 ── 주제별 도구 호출 (공식 통계 → 계산)
      └ 근거 없음: 판정 '확인 안 됨' + 확인 가능한 범위 안내
④ 사실 판정 ── 사실 / 일부 사실 / 사실 아님 / 확인 안 됨
⑤ 노력 매칭 ── 조치 카드 검색 (시행 중 · 직접 관련 · 효과 수치 우선)
⑥ 답장 작성 ── 3단 구조, 선택 언어·말투
⑦ 숫자 대조 ── 답장 숫자 = 도구 결과 확인, 불일치 시 ⑥ 재실행
⑧ 결과 제시 ── 답장 + 근거 카드, [복사] [말투 바꾸기] [언어 바꾸기]
```

| `verify_numbers` | 숫자 대조 | 답장, 도구 결과 | 재작성 |

## 7. 판정 규칙

| 판정 | 기준 (예시) |
|---|---|
| 사실 | 공식 통계가 주장과 같은 방향, 최근 기준 |
| 일부 사실 | 주장 일부만 맞음, 또는 기준(주민·생활인구 등)에 따라 결론이 달라짐 |
| 사실 아님 | 공식 통계가 주장과 반대 방향 |
| 확인 안 됨 | 공식 통계 없음, 또는 개별 사건 단위 질문 |

## 8. 답변 원칙

- 공식 수치 먼저, 보정 수치는 '공식 통계 아님' 표기와 계산 방식 함께
- 불리한 통계도 숨기지 않고 공개
- 개별 사건·인물 실명 미언급, 수사 중 사건 추측 금지
- 국적 등 집단 일반화 금지
- 결항 등 미래 사건은 단정 없이 현재 예보·운항 현황만 안내
- 조치는 시행 중인 것만, 계획 단계는 '추진 중'으로 표시
- 숫자는 모두 도구 결과에서만 인용 (F7 대조)

## 9. 화면 구성

| 영역 | 내용 |
|---|---|
| 왼쪽 · 문의 · 작업 기록 | 손님 메시지 입력, 예시 문의 칩, 단계별 기록 (주장 → 근거 → 판정 → 노력) |
| 오른쪽 · 답장 | 3단 답장 카드 (각 단에 판정 배지·출처), 언어 탭(한·중·영), 말투 선택, [복사] |
| 오른쪽 아래 · 근거 카드 | 출처 링크·기준일 목록, 안심 안내문 만들기 버튼 |

## 10. 비기능 요구사항

| 항목 | 기준 |
|---|---|
| 실행 환경 | 센터 PC (i7-8700 · GTX 1060 · RAM 32GB), `run.bat` 한 번 실행 |
| 화면 | Streamlit 웹앱 (브라우저) |
| LLM | 로컬 LLM(Ollama) 기본, API 선택 가능 |
| 응답 시간 | 문의 1건 30초 이내 목표 |
| 오프라인 | 통계·조치 카드는 로컬 저장본으로 동작, 실시간 운항만 온라인 |
| 개인정보 | 손님 이름·연락처 자동 가림, 문의 원문 저장 안 함 (선택) |
| 보안·반출 | API 키 `.env`, 센터 집계 10 미만 칸 자동 처리 |
| 재현성 | 판정 규칙·숫자 대조 테스트 코드 |
