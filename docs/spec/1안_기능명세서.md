# 1안 쓰레기 예보관 에이전트 — 기능명세서

> 제주 AI·빅데이터 활용 AI Agent 개발 챌린지 · 팀 미나리 백김치 · v1 (2026-11-17)

## 1. 개요

| 항목 | 내용 |
|---|---|
| 한 줄 정의 | 관광객·날씨·연휴·크루즈를 반영해 읍면동별 7일 쓰레기 배출량을 예보하고, 수거 증편 계획과 관련 문서를 만들어 주는 에이전트 |
| 직접 쓰는 사람 | 제주시·서귀포시 청소 담당 주무관 (IT 비전문가) |
| 쓰는 순간 | 매주 월요일 오전 다음 주 수거 계획 수립, 연휴·크루즈 입항 전 |
| 받아 가는 것 | 7일 예보판, 증편 계획서, 위탁업체 요청 문자, 다국어 안내문, 센터 반출 신청서 초안, 검증 보고 |
| 수혜자 | 도민·관광객 (넘치지 않는 클린하우스), 숙박업주 (배출 안내문) |
| 핵심 가치 | 경험·민원 전화 기반 판단 → 데이터 기반 사전 증편, 계획 작성 시간 단축 |

## 2. 사용자 시나리오

| # | 상황 | 사용자 입력 | 에이전트 결과 |
|---|---|---|---|
| S1 | 월요일 주간 계획 | "다음 주 수거 계획 짜 줘" | 지역 되묻기 → 7일 예보 → 증편표 → 계획서·업체 문자·안내문·반출 신청서 → 승인 요청 |
| S2 | 지난주 이상 배출 원인 | "지난주 우도 음식물 왜 늘었어?" | 원인 분해 (관광객·연휴·날씨·미확인 몫) 그래프와 설명 |
| S3 | 계획 변경 | "크루즈 3척으로 늘면 계획 바꿔 줘" | 기존 조회 결과 재사용 → 예보·증편·문서만 갱신 |
| S4 | 정책 검토 | "재활용 요일제 없애면 수거 얼마나 늘어?" | 품목·요일 패턴 기반 필요 수거 횟수 범위 추정 (확장 기능) |

## 4. 에이전트 동작 흐름

```
① 목표 이해 ── 빠진 조건 있으면 되묻기 (지역·기간)
② 계획 수립 ── 필요한 도구와 순서 결정
③ 데이터 조회 ── 과거 배출 · 날씨 · 방문자 · 항공 · 크루즈 · 달력
      └ 외부 API 실패 시: 1회 재시도 → 마지막 저장본 사용 → 보고서에 지연 표시
④ 예보 계산 ── 읍면동 × 7일 + 오차 구간
⑤ 자기 검증 ── 지난 4주 백테스트, 기준선보다 나쁘면 기준선 채택
⑥ 조치 계산 ── 등급 → 증편 횟수 → 처리시설 여력 확인
⑦ 완성물 작성 ── 계획서 · 문자 · 안내문 · 반출 신청서
⑧ 반출 검사 ── 10 미만 칸 · 개인 식별 항목 확인
⑨ 승인 요청 ── 담당자 확인 사항 제시 → 승인 / 수정
```

## 7. 출력 규칙

- 숫자는 모두 Python 코드 계산, LLM은 도구 선택·문장 작성만 담당
- 모든 답에 사용 데이터·기간·오차 표시
- 외부 데이터 지연·대체 사용 시 문서에 명시
- 예보가 기준선보다 부정확하면 기준선으로 전환하고 그 사실 보고
- 개인 식별 정보(RFID 태그번호 등) 미출력, 배출지·읍면동 합계만 사용

## 8. 데이터 선순환 구조 (팀원 제안)

기존 데이터로 시작하되, **쓸수록 새 데이터가 쌓이고 그 데이터로 예보가 더 정확해지는 구조**.

```
예보 → 증편 계획 → 현장 실행 → 결과 기록 → 자동 보정 → 다음 주 더 정확한 예보
 ▲                                                          │
 └──────────────────────────────────────────────────────────┘
```

### 사용하면서 쌓이는 데이터

| 쌓이는 데이터 | 누가·어떻게 | 무엇이 좋아지나 |
|---|---|---|
| 증편 실행 여부·실제 수거량 | 담당자·위탁업체가 계획서에 체크·입력 | 증편 기준(평소 110%, 1회 2.5t)을 동네별 실제 값으로 보정 |
| 클린하우스 넘침 여부 (O/X) | 수거 기사·읍면동 담당 버튼 기록 | 같은 배출량이라도 넘치는 동네를 학습 → 동네별 '넘침 기준' |
| 예보 vs 실제 오차 | 매주 자동 계산 | 오차 큰 동네·요일의 보정값 자동 조정 |
| 담당자 수정 내역 | 승인 전 수정한 증편 횟수·문구 | 현장 감각을 반영한 기본값·문서 템플릿 개선 |
| 질문 기록 (익명) | 자주 묻는 질문 자동 집계 | 예시 질문·화면 순서 개선 |

### 선순환 효과
- 첫 주는 공공 데이터 기반 예보, 몇 주 뒤부터는 **제주 현장 기록이 더해진 예보**
- 쌓인 '넘침 기록'은 클린하우스 증설·재배치 검토의 새 근거
- 동네별 넘침 기록·실제 수거량은 개인정보 없는 집계 데이터로 **제주데이터허브 공개 데이터로 환원** 가능 (결과물의 센터 귀속 규정과도 부합)

### 원칙
- 개인 식별 정보 미수집, 동네·날짜 단위 집계만 저장
- 자동 보정 전후 오차를 함께 기록, 나빠지면 이전 값으로 복귀
- MVP는 기록 기능(F14), 자동 보정(F15)은 시연용 1회 실행으로 구현
