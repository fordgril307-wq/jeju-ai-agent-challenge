# 2안-A 밤길 안심 예보관 에이전트 — 기능명세서

> 제주 AI·빅데이터 활용 AI Agent 개발 챌린지 · 팀 미나리 백김치 · v1 (2026-11-17)

## 1. 개요

| 항목 | 내용 |
|---|---|
| 한 줄 정의 | 밤 생활인구·위험 지도·조명·CCTV·달력을 묶어 읍면동별 7일 야간 안전 수요를 예보하고, 순찰·조명 우선순위와 관련 문서를 만들어 주는 에이전트 |
| 직접 쓰는 사람 | 제주자치경찰단 생활안전·관광 순찰 계획 담당 (IT 비전문가) |
| 쓰는 순간 | 매주 금요일 다음 주 야간 순찰표 작성, 야간 행사·크루즈 입항 전, 분기 조명·CCTV 사업 검토 |
| 받아 가는 것 | 7일 안전 수요 예보판, 순찰 권고표, 조명·CCTV 보강 후보, 범죄율 팩트체크 답변, 한·중·영 밤길 안내문, 주간 보고서, 센터 반출 신청서 초안 |
| 2차 사용자 | 도 안전정책·도로 조명 부서, CCTV 통합관제센터, 지구대·파출소, 자율방범대 |
| 수혜자 | 1인 관광객, 여성 야간 보행자, 심야 근무 도민 |
| 핵심 가치 | 신고 기록·현장 감각 기반 판단 → 사람 많고 어두운 곳·시간에 순찰·조명 자원 집중 |

## 2. 예측 대상 — '범죄'가 아닌 '안전 수요'

```
안전 수요 지수 = 밤 인원 × 위험 가중 × 밝기·감시 부족 × 달력·날씨
```

| 요소 | 의미 | 데이터 묶음 | 성격 |
|---|---|---|---|
| 밤 인원 | 21~03시 읍면동 생활인구 (주민 + 관광객), 심야 상권 활동 | N 밤 사람 수 | 7일 예보값 |
| 위험 가중 | 범죄주의구간·폭력 사고 밀도 | P 사건·위험 | 고정 지도값 (1년치) |
| 밝기·감시 부족 | 가로등·보안등·CCTV 밀도의 역수 | I 안전 인프라 | 고정 지도값 |
| 달력·날씨 | 주말·연휴 전날, 야간 행사, 비, 일몰 시각 | T 날씨·달력·행사 | 7일 입력값 |

- 공개 범죄 통계가 연·경찰서 단위라 범죄 건수 예측은 하지 않음 → 예보 대상은 검증 가능한 '밤 인원', 나머지는 출처·기준일이 있는 고정값
- 가중치는 담당자 검토로 조정하는 설정값

## 3. 사용자 시나리오

| # | 상황 | 사용자 입력 | 에이전트 결과 |
|---|---|---|---|
| S1 | 금요일 주간 순찰 계획 | "다음 주 밤 순찰 어디부터?" | 지역 되묻기 → 7일 예보 → 1~3단계 구역·시간대 → 순찰 권고표·보고서 → 승인 요청 |
| S2 | 야간 행사 대비 | "탑동 야간 행사 날 인력 얼마나?" | 행사 조건 반영 재계산 → 등급 변화, 순찰조·자율방범대 협조 규모 |
| S3 | 조명 사업 검토 | "가로등 더 달 곳 TOP 5" | 밤 인원 많고 어두운 후보 5곳과 근거 수치 |

| S5 | 온라인 괴담 대응 | "제주 범죄율 1위 진짜야?" | 공식 수치 + 보정치(비공식 표기) + 정의 차이 설명 |
| S6 | 반출 | "이 결과 밖으로 가져가도 돼?" | 반출 기준 검사 결과와 신청서 초안 |

## 5. 에이전트 동작 흐름

```
① 목표 이해 ── 빠진 조건 있으면 되묻기 (지역·기간·시간대)
② 계획 수립 ── 필요한 도구와 순서 결정
③ 데이터 조회 ── 밤 인원 · 7일 관광 수요 · 날씨·일몰 · 달력·행사 · 위험면 · 가로등·CCTV
      └ 외부 API 실패 시: 1회 재시도 → 마지막 저장본 사용 → 보고서에 지연 표시
④ 예보 계산 ── 읍면동 × 7일 × 밤 시간대 지수 + 오차 구간
⑤ 자기 검증 ── 지난 4주 백테스트, 기준선보다 나쁘면 기준선 채택
⑥ 조치 계산 ── 등급 → 순찰 권고 → 사각지대 후보
⑦ 완성물 작성 ── 순찰 권고표 · 보고서 · 밤길 안내문 · 반출 신청서
⑧ 반출 검사 ── 10 미만 칸 · 개인 속성 항목 확인
⑨ 승인 요청 ── 담당자 확인 사항 제시 → 승인 / 수정
```

## 8. 설계 원칙 (민감 주제)

| 원칙 | 내용 | 이유 |
|---|---|---|
| 1. 예측 대상 | '범죄'가 아닌 '안전 수요' | 범죄 통계가 연·경찰서 단위, 개인·사건 예측은 부적절 |
| 2. 개인 속성 제외 | 국적·성별·연령 등 개인 속성 점수 미사용, 외국인 범죄 통계는 팩트체크 전용 | 특정 집단 낙인 방지 |
| 3. 표현 방식 | 내부 화면은 '순찰·조명 우선도', 외부 공개는 '밝은 길 안내' 형태 | 동네 낙인·부동산 영향 방지 |
| 4. 사건 비추적 | 개별 사건 언급·추적 기능 없음, 공식 통계만 인용 | 2차 피해·추측 확산 방지 |
| 5. 집계 반출 | 센터 유동인구는 집계만, 10 미만 칸 자동 묶음 | 센터 반출 기준 준수 |
| 6. 보정치 표기 | 생활인구 보정 범죄율은 '공식 아님'과 계산 방식 함께 표시 | 통계 해석 논란 방지 |

## 9. 출력 규칙

- 숫자는 모두 Python 코드 계산, LLM은 도구 선택·문장 작성만 담당
- 모든 답에 사용 데이터·기간·기준일·오차 표시
- 외부 데이터 지연·대체 사용 시 문서에 명시
- 예보가 기준선보다 부정확하면 기준선으로 전환하고 그 사실 보고
- 질문이 애매하면 되묻기, 데이터가 없으면 '없음'과 대안 제시, 개별 사건 질문은 답변 범위 밖 안내

## 10. 데이터 선순환 구조 (팀원 제안)

기존 데이터로 시작하되, **쓸수록 현장 기록이 쌓이고 그 기록으로 예보와 우선순위가 더 정확해지는 구조**.

```
예보 → 순찰 권고 → 현장 순찰 → 결과 기록 → 자동 보정 → 다음 주 더 정확한 예보
 ▲                                                         │
 └─────────────────────────────────────────────────────────┘
```

### 사용하면서 쌓이는 데이터

| 쌓이는 데이터 | 누가·어떻게 | 무엇이 좋아지나 |
|---|---|---|
| 순찰 실행 기록 | 담당자·순찰조가 권고표에 체크 | 권고 대비 실행률, 동네별 필요 순찰량 보정 |
| 현장 특이사항 | 어두운 구간·고장 가로등·취약 시설을 버튼·지도 표시 | 밝기 부족 값을 현장 기준으로 갱신 → 조명 사업 근거 |
| 예보 vs 실제 밤 인원 오차 | 매주 자동 계산 | 오차 큰 동네·요일 보정값 자동 조정 |
| 담당자 수정 내역 | 승인 전 수정한 등급·순찰 횟수 | 현장 감각을 반영한 가중치·기본값 개선 |
| 질문 기록 (익명) | 자주 묻는 질문 자동 집계 | 예시 질문·화면 순서 개선 |

### 선순환 효과
- 첫 주는 공공 데이터 기반 예보, 몇 주 뒤부터는 **제주 현장 순찰 기록이 더해진 예보**
- 쌓인 '어두운 구간' 기록은 도로 조명·CCTV 사업의 새 근거
- 개인정보 없는 동네·주 단위 집계는 **제주데이터허브 공개 데이터로 환원** 가능 (결과물의 센터 귀속 규정과도 부합)

### 원칙
- 개인 식별 정보·사건 정보 미수집, 동네·날짜·시간대 집계만 저장
- 자동 보정 전후 오차를 함께 기록, 나빠지면 이전 값으로 복귀
- MVP는 기록 기능(F13), 자동 보정(F14)은 시연용 1회 실행으로 구현

## 11. 비기능 요구사항

| 항목 | 기준 |
|---|---|
| 실행 환경 | 센터 PC (i7-8700 · GTX 1060 · RAM 32GB), `run.bat` 한 번 실행 |
| 화면 | Streamlit 웹앱 (브라우저), 지도는 오프라인 타일 또는 읍면동 경계 도형 |
| LLM | 로컬 LLM(Ollama) 기본, API 선택 가능 — 설정 파일로 전환 |

| 오프라인 | 외부 API 실패 시 저장본으로 전체 흐름 동작 |
| 보안 | API 키는 `.env`, 저장소·제출물 미포함 |
| 반출 | 노트북 출력(`data.head()` 등) 제거 후 제출, 10 미만 칸 자동 처리 |
| 재현성 | 테스트 코드 (지수 계산·등급·순찰 권고·반출 검사), 고정 난수 |
